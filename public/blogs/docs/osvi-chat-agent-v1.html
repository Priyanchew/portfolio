Chat Agent v1: Architecture, Schema & Implementation Plan

A LangGraph-powered configurable chat agent that lives inside the existing osvi-agentic-platform FastAPI service. Mirrors the voice agent's runtime-independent pattern: Ruby owns config writes, the chat service only reads config and writes operational state. Internal-only deployment, Ruby-proxied, full Postgres durability via AsyncPostgresSaver 3.x.

Executive readout

Four new application tables plus four mirrored LangGraph checkpoint tables — all owned by Rails. Twelve implementation phases, end-to-end TDD'd. Full POC HITL feature set (whisper, tell, takeover, end, close, observe, leave) ships in v1; only @-mention notifications are deferred. Sessions close on explicit request only — no auto-idle, no webhooks, ever.

How it runs

Postgres-durable, multi-instance safe

  • AsyncPostgresSaver 3.x checkpoints state per thread_id (= session UUID).
  • Per-conv concurrency via Postgres advisory locks — no sticky routing.
  • SQL mirror tables for admin/audit; graph wins on divergence (reconcile_on_boot).
Guardrails

Hard rules, no exceptions

  • Ruby owns all migrations — including LangGraph checkpoint tables.
  • Python never calls checkpointer.setup().
  • No public DNS, no public TLS, no webhooks, no auto-idle/close — ever.
02 · Architecture

The chat service is internal-only.
Ruby is the only door.

A new module inside the same FastAPI app the voice service runs in. Reuses Postgres, Redis, accounts, memory, S3, and the existing deployment story. LangGraph state is checkpointed to Postgres via AsyncPostgresSaver; an application mirror of sessions and messages keeps fast SQL queries cheap.

Runtime topology

Request path Postgres I/O Redis I/O Admin DDL (Ruby owned)
Runtime independence

Identical posture to voice. Restart any replica freely. Add replicas behind an internal load balancer freely. Agent config is read-only at runtime.

Public exposure rule

No public route, no public DNS, no public TLS cert on the chat service. Reachable only from Ruby's VPC / security group. Same posture as any other internal microservice.

Multi-instance safety

Sticky routing not required. Per-conv concurrency via Postgres advisory locks (pg_try_advisory_xact_lock(hashtext(session_id))) — released automatically on transaction commit.

Read / write split

Ruby owns every DDL change. The chat service reads agent config and writes only operational state.

03 · Database Map

Eight new tables.
Two storage systems.
One source of truth.

Four application tables (Ruby admin + chat-svc operational writes) and four LangGraph checkpoint tables (mirrored DDL, owned by Rails). The session UUID is also the LangGraph thread_id; the LangChain message.id is also the messages-mirror PK.

New application table LangGraph checkpoint (mirrored) Existing table (read only) Foreign key Logical / cross-system join

Mapping rules

  1. One session = one LangGraph thread. chat_agents_sessions.id (UUID, cast to text) is passed as config["configurable"]["thread_id"] on every graph invocation.
  2. One LangChain message = one row in chat_agents_messages. The streaming adapter inserts using message.id as PK; INSERTs use ON CONFLICT (id) DO NOTHING for idempotency.
  3. Checkpoints are the source of truth. If the application mirror diverges from a checkpoint (crash mid-write), reconcile_on_boot pulls graph state via graph.aget_state(config) and overwrites the mirror's coarse fields.
  4. help_requested lives in both places. ConvState["help_requested"] drives prompt assembly; chat_agents_sessions.help_requested is the dashboard mirror.
  5. Session lifecycle (ended_at) is application-only. LangGraph has no "closed" concept — we model "closed" by rejecting new messages when ended_at IS NOT NULL.

05 · Configuration shapes

Three JSONB columns. Clear separation of concerns.

agent_config holds tools and (for multi-prompt) the state machine. llm_config holds per-agent LLM values validated by the template's config_schema. config holds non-LLM runtime settings only.

Tools list, flat shape

How state machines run inside one compiled graph

The graph compiles once at boot. agent_type=multi_prompt means the ai_agent node reads ConvState["current_state"] per-turn and selects which prompt & tools to inject via configurable. State transitions are emitted by auto-generated per-edge tools (transition_to_<state>) — same pattern voice uses.

Blocker · #1 conversation_service.py · Task 10.2

create_llm_for_chat() is voice-only and returns a LiveKit LLM

The plan calls create_llm_for_chat(cfg_dict.get("llm_config") or {}). The actual signature in services/provider_helper_service.py:303 takes an AgentLLMConfiguration ORM object (it accesses config.llm_provider_template.provider and config.config_values) — not a dict — and returns a livekit.plugins.openai.LLM. That's not a LangChain LLM and will not work with LangGraph's .bind_tools() / .ainvoke().

Fix: add a sibling helper in services/provider_helper_service.py:

def create_langchain_chat_llm(provider: str, llm_config: dict):
    """Return a LangChain ChatModel for chat-agent use."""
    from langchain_openai import ChatOpenAI
    if provider in {"openai"}:
        return ChatOpenAI(
            model       = llm_config.get("model", "gpt-4o-mini"),
            temperature = llm_config.get("temperature", 0.0),
            max_tokens  = llm_config.get("max_tokens", 1024),
            api_key     = get_config().openai_api_key,
        )
    # Phase-1 supports openai only; extend per template.provider as templates are added.
    raise ValueError(f"unsupported provider: {provider}")

Then in conversation_service.py:

# Resolve provider from the template (cached read)
template = await fetch_llm_provider_template(cfg_dict["llm_provider_template_id"])
llm = create_langchain_chat_llm(template.provider, cfg_dict.get("llm_config") or {})
Blocker · #2 database/model/chat_agent_session.py · Task 2.1 database/model/chat_agent_message.py · Task 2.1

metadata is a reserved attribute on SQLAlchemy declarative models

The plan defines metadata = Column("metadata", JSONB, ...) on both ChatAgentsSession and ChatAgentsMessage. SQLAlchemy 2.x raises InvalidRequestError: Attribute name 'metadata' is reserved when using the Declarative API. because Base.metadata is already on the class.

Fix: rename the Python attribute, keep the column name "metadata":

# BEFORE (will raise at import time)
metadata = Column("metadata", JSONB, nullable=False, default=dict)

# AFTER (works)
meta = Column("metadata", JSONB, nullable=False, default=dict)

All call-sites that read .metadata on these ORM rows must update to .meta. The DB column name stays metadata; only the Python attribute changes — no migration needed.

Watch · #3 memory_service · Task 10.2

get_contact_context expects agent_id: Optional[int]

The signature in services/memory_service.py:117 declares agent_id: Optional[int] = None. The plan passes cfg_dict["id"], which is the chat_agent UUID as a string. Postgres comparison may coerce-or-fail depending on the join target column type.

Watch · #5 support_service.py · Task 10.3

Inactivity timer is per-process — not multi-instance safe

_inactivity_tasks: dict[str, asyncio.Task] = {} is a module-level dict scoped to one Python process. If session S is taken over on replica A and replica A then crashes, replica B has no timer armed for S. The takeover will never auto-resume until B's reconcile_on_boot runs — which only happens at B's next boot, not on A's death.

Mitigations (pick one for v1):

  • Document the limitation in deployment notes; rely on operator to issue /end manually if a replica dies mid-takeover.
  • Run a periodic background sweep on every replica that reads chat_agents_sessions for stale takeovers (where last_support_msg_at < NOW() - timeout) and arms a timer locally — first replica to win the advisory lock wins the auto-resume.
  • Move the timer state to Postgres (e.g. chat_agents_sessions.takeover_deadline_at) and have a sweeper job act on it. Cleanest, but adds a new column & a sweeper worker.

v1 plan currently does none of these. Either pick a mitigation or accept the limitation explicitly.

Watch · #6 app/utils/python_engine_utils.rb · Task 1.7 app/controllers/chat_agent_sessions_controller.rb

Rails streaming proxy needs a real HTTP-streaming adapter

The plan's controller does self.response_body = PythonEngineUtils.request_for_chat_agent_message(session.id, body) after setting stream: true. Stock HTTParty / Faraday .post(...) calls return a fully-buffered response — assigning that to self.response_body defeats streaming. The chunked NDJSON from Python will be collected in memory and only forwarded after the Python turn completes, killing the token-by-token UX.

Fix: implement request_for_chat_agent_message as a true streaming HTTP call — return an object that responds to .each(&block) and yields each chunk as it arrives. Concrete implementation using Net::HTTP:

def self.request_for_chat_agent_message(session_id, body)
  uri = URI(chat_agent_url("/sessions/#{session_id}/messages"))
  Enumerator.new do |yielder|
    Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") do |http|
      req = Net::HTTP::Post.new(uri)
      req["Content-Type"] = "application/json"
      req.body = body.to_json
      http.request(req) do |res|
        res.read_body { |chunk| yielder << chunk }
      end
    end
  end
end

The controller can then assign the enumerator directly: self.response_body = enumerator. Rails will iterate it and flush each chunk as it arrives.

Watch · #7 tool_factory.py · Task 7.2 request_human_help · Task 7.1 Ruby admin · Task 1.6

Voice's human_transfer_tool isn't reusable — but the existing Slack notifier is

The chat ToolFactory deliberately excludes voice-only tool types (end_call, detect_voice_mail, language_switch, warm_transfer, transfer_call_to_human_agent). Voice's human_transfer_tool is SIP/LiveKit-specific (warm transfer via SIP REFER) and has no analogue in text chat. The chat handoff path is the POC's request_human_help — an asynchronous flag, not a synchronous transfer.

Gap A — silent drop. _VOICE_ONLY entries in build_tools_for_agent() use a continue with no log. If an admin pastes a voice agent's agent_config.tools into a chat agent (or copy-pastes a tool entry by mistake), the tool silently disappears at runtime and the AI behaves as if it was never configured. No error in Ruby admin, no error at boot, no log line.

Existing infra worth wiring in

services/notifications/ already ships a SlackNotificationChannel (incoming webhook) and a NotificationService singleton with a Strategy-pattern fan-out. Today it's only fired from post_call_service.py:281 as notify_call_completed(...) after voice calls. Nothing chat-side touches it. Voice's human_transfer_tool doesn't fire it either — it just does the SIP transfer.

Gap B — chat help-request goes nowhere visible. v1's request_human_help only flips help_requested = TRUE and writes a help_requested event row. Operators have to poll the dashboard to find sessions that need help. The existing Slack channel is right there and trivial to extend.

Pick one (or both):

  • (A) Just keep the silent flag, plus admin validation. In Ruby's ChatAgentsController#create_params + a model-level validator, reject any agent_config.tools[*].tool_type that's in the voice-only set. Operators rely on the dashboard to find help-requested sessions. Cheapest. No new code paths beyond Ruby validation.
  • (B) Wire request_human_help into the existing Slack notifier. After the SQL writes (set flag + insert event), call await get_notification_service().notify_help_requested(...). Operators get a Slack ping with the session ID, agent name, customer hint, the AI's stated reason, and a deep link to the dashboard. Concrete steps:
    1. Add send_help_requested_notification to NotificationChannel ABC.
    2. Add HelpRequestedPayload dataclass — session_id, agent_uuid, agent_display_name, account_name, customer_id, reason, dashboard_url.
    3. Implement SlackNotificationChannel.send_help_requested_notification with chat-flavored message text.
    4. Add NotificationService.notify_help_requested(...) using the same fan-out pattern notify_call_completed uses.
    5. Extend request_human_help body with a non-fatal try/except wrapping the notify call (same defensive pattern voice uses at post_call_service.py:287-288).
    Reuses every existing piece. SLACK_WEBHOOK_URL is already wired in config/config.py. No new secrets, no new infra.
  • (C) Both. Validate at admin time (primary defense against the silent drop) AND wire the Slack ping (gives operators a real-time signal, kills dashboard polling). Recommended for v1 since both are small.
Open question for the team

Should the Slack ping fire on every help-request, or only when no operator is currently online? The latter needs a presence model we don't have in v1. Default recommendation: fire on every help-request in v1 (simple, predictable); revisit if Slack noise becomes a problem.

from psycopg_pool import AsyncConnectionPool

_pool: AsyncConnectionPool | None = None

async def open_pool(min_size: int = 2, max_size: int = 10) -> AsyncConnectionPool:
    global _pool
    if _pool is None:
        _pool = AsyncConnectionPool(
            conninfo=_conninfo(),
            min_size=min_size, max_size=max_size,
            kwargs={"autocommit": True, "row_factory": dict_row},
            open=False,
        )
        await _pool.open()
    return _pool

async def close_pool() -> None:
    global _pool
    if _pool is not None:
        await _pool.close()
        _pool = None

def get_pool() -> AsyncConnectionPool:
    if _pool is None:
        raise RuntimeError("async pool not open; call await open_pool() in lifespan")
    return _pool

async def ai_agent(state: ConvState, config: RunnableConfig) -> dict[str, Any]:
    configurable = config.get("configurable") or {}
    llm   = configurable["llm"]
    tools = configurable["tools"]
    whispers         = state.get("pending_whispers") or []
    guidance_history = state.get("support_guidance_history") or []
    state_prompt     = configurable.get("state_system_prompt")

    prompt: list[Any] = [SystemMessage(content=state_prompt or SYSTEM_PROMPT)]
    if guidance_history:
        prompt.append(SystemMessage(content="Private support guidance history:\n" +
                                          "\n".join(f"- {g}" for g in guidance_history[-20:])))
    prompt.extend(state["messages"])
    if whispers:
        prompt.append(SystemMessage(content="New private support guidance for this turn:\n" +
                                          "\n".join(f"- {w}" for w in whispers)))

    response = await llm.bind_tools(tools).ainvoke(prompt)
    update: dict[str, Any] = {"messages": [response], "pending_whispers": []}

    tool_calls = getattr(response, "tool_calls", None) or []
    if any((tc.get("name") if isinstance(tc, dict) else getattr(tc, "name", None)) == "request_human_help" for tc in tool_calls):
        update["help_requested"] = True
    return update


async def human_gate(state: ConvState) -> dict[str, Any]:
    interrupt(None)
    return {}
5.4build_graph — topology▶

START → router → (ai_agent ⇄ tools | human_gate) → END. Same shape as POC.

def build_graph(checkpointer, tools):
    g = StateGraph(ConvState)
    g.add_node("ai_agent",   ai_agent)
    g.add_node("human_gate", human_gate)
    g.add_node("tools", ToolNode(list(tools)))

    g.add_conditional_edges(START, router, {"ai_agent": "ai_agent", "human_gate": "human_gate"})

    def _needs_tools(state):
        last = state["messages"][-1] if state["messages"] else None
        if isinstance(last, AIMessage) and getattr(last, "tool_calls", None):
            return "tools"
        return END

    g.add_conditional_edges("ai_agent", _needs_tools, {"tools": "tools", END: END})
    g.add_edge("tools", "ai_agent")
    g.add_edge("human_gate", END)
    return g.compile(checkpointer=checkpointer)

7.2ToolFactory — chat-flavored▶

Drops voice-only tool types (end_call, detect_voice_mail, language_switch, warm_transfer, voice's SIP human_transfer_tool). Auto-generates per-edge transition_to_<state> tools for multi_prompt.

_VOICE_ONLY = {
    "end_call", "detect_voice_mail", "language_switch", "warm_transfer",
    "transfer_call_to_human_agent",  # voice's SIP-only HumanTransferTool
}

def build_tools_for_agent(agent_config: dict | None, current_state: str | None = None) -> list:
    tools = []
    if not agent_config:
        return tools

    if "states" in agent_config and current_state:
        # multi_prompt: global + state tools + auto transition tools per edge
        global_tools = agent_config.get("global_tools", []) or []
        states_map = {s["name"]: s for s in agent_config.get("states", [])}
        state_cfg = states_map.get(current_state, {})
        entries = [*global_tools, *(state_cfg.get("tools", []) or [])]
        for edge in (state_cfg.get("edges") or []):
            tools.append(_make_transition_tool(edge, from_state=current_state))
    else:
        entries = agent_config.get("tools", []) or []

    for entry in entries:
        ttype = entry.get("tool_type")
        if ttype in _VOICE_ONLY:
            continue
        if ttype == "request_human_help":
            tools.append(request_human_help)
        elif ttype == "search_rag":
            tools.append(_build_search_rag(entry))
        elif ttype == "custom_tool":
            tools.append(_build_custom_tool(entry))
    return tools

async def run_search_rag(query: str, entry: dict[str, Any]) -> str:
    agent_id     = entry["__runtime__"]["agent_id"]
    account_name = entry["__runtime__"]["account_name"]
    index_type   = entry.get("index_type", "hybrid")
    handler = create_rag_handler(

        namespace=get_namespace(account_name),
        agent_id=agent_id, account_name=account_name,
        doc_ids=get_agent_doc_ids(agent_id) or None,

async def run_custom_tool(kwargs: dict, entry: dict) -> str:
    method = (entry.get("method") or "GET").upper()
    async with httpx.AsyncClient(timeout=float(entry.get("timeout", 10))) as client:
        r = await client.request(
            method, entry["url"],
            headers=entry.get("headers") or {},
            json=kwargs if method in {"POST", "PUT", "PATCH"} else None,
            params=kwargs if method == "GET" else None,
        )
        r.raise_for_status()
        try: return json.dumps(r.json())
        except ValueError: return r.text

9.1Command types + parser (port from POC)▶

Verbs: /whisper, /tell, /takeover, /end, /close, /observe, /leave. Plain text in ai mode → Whisper; in takeover mode by holder → ChatMessage; by other → ParseError("conversation_held_by:...").

def parse(text: str, *, mode: Literal["ai", "takeover"],
          current_user: str, active_human: str | None) -> ParsedCommand:
    text = text.strip()
    if not text:
        raise ParseError("invalid_or_incomplete_slash_command")

    if not text.startswith("/"):
        if mode == "takeover":
            if active_human is None or active_human != current_user:
                raise ParseError(f"conversation_held_by:{active_human}")
            return ChatMessage(text=text)
        return Whisper(text=text)

    head, _, rest = text.partition(" ")
    verb = head.lstrip("/").lower()
    rest = rest.strip()

    if verb == "whisper":  return Whisper(text=rest) if rest else _err()
    if verb == "tell":     return Tell(text=rest)    if rest else _err()
    if verb == "takeover": return TakeoverIntent()
    if verb == "end":      return End()
    if verb == "close":    return Close()
    if verb == "observe":  return Observe()
    if verb == "leave":    return Leave()
    raise ParseError("invalid_or_incomplete_slash_command")

10.2Conversation service — advisory lock + post_user_message▶
Plan amendment · blocker #1

Replace create_llm_for_chat(cfg_dict.get("llm_config") or {}) with the new sibling helper create_langchain_chat_llm(template.provider, llm_config). The current voice helper returns a LiveKit LLM, which is incompatible with LangGraph.

Multi-instance-safe via Postgres advisory lock keyed on blake2b(session_id)[:8]. Lock released automatically on transaction commit.

def _conv_lock_key(conv_id: str) -> int:
    h = hashlib.blake2b(conv_id.encode(), digest_size=8).digest()
    n = int.from_bytes(h, "big", signed=False)
    return n - (1 << 63) if n >= (1 << 63) else n


async def post_user_message(*, graph, pool, conv_id, agent_id, user_text, account_name):
    async with pool.connection() as conn:
        async with conn.transaction():
            if not await _try_advisory_lock(conn, conv_id):
                raise ConvBusyError("conv_busy")

            if cfg_dict is None:
                raise ValueError("chat_agent_inactive_or_missing")

Takeover inactivity

TAKEOVER_INACTIVITY_TIMEOUT_S (default 60s) auto-resumes AI when the holding operator stops typing. This is a HITL responsiveness feature — not a session-lifecycle auto-close (which is forbidden).

Auto-idle / auto-close timers · webhooks · public exposure of the chat service · checkpointer.setup() · DDL from Python.

10 · Locked assumptions

Eleven decisions you can rely on.

  1. LangGraph chat lives inside osvi-agentic-platform; LiveKit voice path is untouched.
  2. Internal-only deployment. Chat service has no public DNS, no public TLS. Only Ruby reaches it, via private network.
  3. Ruby owns all migrations, including the four LangGraph checkpoint tables (mirrored as Rails migrations).
  4. Python never calls checkpointer.setup(). checkpoint_migrations is pre-seeded by Ruby so AsyncPostgresSaver sees the schema as ready.
  5. Tools live in agent_config JSONB. LLM config lives in llm_config JSONB validated by llm_provider_template.config_schema. Legacy tools & agent_llm_configurations tables are not extended.
  6. request_human_help tool is ported verbatim from the POC at osvi-support-hitl/backend/agent/tools.py — adapted only to write to our schema and skip the EventBus call.
  7. Full POC HITL feature set (whisper / tell / takeover / end / close / observe / leave). Only deferral: @-mention notifications + the FK-grade active_human_user_id column.
  8. The takeover inactivity auto-resume timer is in scope. It is a HITL responsiveness feature, not a session-lifecycle auto-close.
  9. HTTP chunked streaming response is the streaming model. No WebSocket. No SSE. No webhooks — ever.
  10. No auto idle / auto close timers — ever. Sessions close only on explicit close request.
  11. Pinned versions (verified on PyPI 2026-05-07): langgraph ~= 1.1.10, langgraph-checkpoint-postgres ~= 3.0.5, langchain-core ~= 1.3.3, langchain-openai ~= 1.2.1, psycopg[binary,pool] ~= 3.3.4.
